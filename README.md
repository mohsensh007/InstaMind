# InstaMind — دستیار هوشمند دایرکت اینستاگرام (C# / ASP.NET Core)

یک برنامهٔ کامل و آمادهٔ اجرا که پیام‌های دایرکت یک اکانت اینستاگرام حرفه‌ای را می‌گیرد،
با هوش مصنوعی جواب می‌دهد و **فقط دربارهٔ موضوع‌هایی که خودت تعیین می‌کنی** حرف می‌زند؛
هر چیز بیرون از آن با یک پاسخ ثابت رد می‌شود.

نوشته‌شده با **C# و ASP.NET Core (.NET 10)** و یک رابط کاربری فارسی راست‌به‌چپ.

---

## چرا وب‌اپ و نه اپ دسکتاپ؟

چون اینستاگرام پیام‌های جدید را با **وبهوک** (یک آدرس HTTPS عمومی) به برنامه می‌فرستد.
یعنی برنامه باید همیشه در دسترس باشد و یک سرور HTTP داشته باشد. یک اپ دسکتاپ هم برای این کار
به یک سرور واسط نیاز دارد. پس بهترین انتخاب:

| گزینه | مناسب است؟ | توضیح |
|---|---|---|
| **ASP.NET Core (همین پروژه)** | ✅ | یک جا هم وبهوک را می‌گیرد، هم پنل مدیریت دارد، هم با `dotnet run` روی ویندوز/لینوکس اجرا می‌شود. |
| WinForms / WPF | ⚠️ | رابط گرافیکی خوب است ولی برای وبهوک باید همیشه روشن بماند و پورت عمومی داشته باشد؛ پیچیدگی بیشتر. |
| اپ موبایل | ❌ | سرور همیشه روشن نیست و دریافت وبهوک سخت می‌شود. |

پس: **زبان C# حفظ شده، ولی شکل پروژه یک وب‌اپ سبک است** (بدون نیاز به Node.js یا دیتابیس جدا).

## امکانات

- **چند صفحهٔ اینستاگرام هم‌زمان**: هر پیج را جداگانه وصل کن، لیست صفحه‌های متصل را در یک صفحهٔ جدا ببین و برای هرکدام «تست اتصال»، «تمدید توکن» و «حذف» داشته باش.
- **چند سرویس هوش مصنوعی هم‌زمان**: OpenAI، OpenRouter، Groq، Ollama و… را جداگانه اضافه و تست کن؛ لیست کل APIهای متصل هم در یک صفحهٔ جدا هست.
- **مسیریابی دلخواه**: هر صفحه می‌تواند از یک AI جداگانه استفاده کند، یا چند صفحه روی یک AI مشترک باشند.
- **تست اتصال دوطرفه**: دکمهٔ تست کنار هر صفحه (توکن همان صفحه را با Graph API چک می‌کند) و دکمهٔ تست کنار هر سرویس AI (یک پاسخ آزمایشی واقعی از مدل می‌گیرد).
- **محاسبهٔ مصرف توکن**: میانگین توکن هر پاسخ از فراخوانی‌های واقعی اندازه گرفته می‌شود؛ با وارد کردن «موجودی توکن» هر سرویس، برنامه تخمین می‌زند هر AI حدوداً چند پاسخ دیگر می‌تواند بدهد.
- **سقف مصرف روزانه برای هر صفحه**: برای هر پیج می‌توانی سقف تعداد پاسخ یا سقف توکن در روز بگذاری (۰ = بدون سقف)؛ با پر شدن سقف، پاسخ خودکار همان روز متوقف می‌شود و فردا خودکار ریست می‌شود. مقادیر را هر وقت بخواهی بالا/پایین می‌کنی.
- **اتصال به دایرکت اینستاگرام** از طریق Instagram Messaging API رسمی متا (وبهوک + ارسال پیام)
- **حالت مرورگر (Selenium)**: یک کروم واقعی با نشست خودت، خواندن صندوق دایرکت، تایپ حرف‌به‌حرف، فاصلهٔ بین ارسال‌ها، مکث هر مخاطب، سقف روزانه — با ریسک خودش (بخش مخصوصش را بخوان)
- **ورود ذخیره‌شده** (اختیاری): یوزرنیم و پسورد را رمزنگاری‌شده نگه می‌دارد و خودش وارد می‌شود؛ کد دو مرحله‌ای را خودت می‌زنی
- **۲۴ ساعته یا بازهٔ ساعتی**: پاسخگویی شبانه‌روزی، یا فقط داخل ساعتی که خودت تعیین می‌کنی
- **سه پروفایل سرعت**: آرام / متعادل / سریع — «سریع» یعنی Seen و جواب در حدود نیم دقیقه
- **حالت سندباکس** برای تست کامل بدون هیچ ریسک و بدون نیاز به توکن
- **پرامپت شخصیت‌محور**: معرفی کسب‌وکار، لحن، زبان، طول پاسخ، ایموجی
- **موضوعات مجاز و ممنوع** به‌صورت لیست
- **سه لایهٔ گارد‌ریل**:
  1. پرامپت سخت‌گیرانه + قانون «خارج از موضوع = پاسخ ثابت»
  2. دروازهٔ موضوع با یک فراخوانی جداگانهٔ مدل (قابل خاموش کردن)
  3. فیلتر ورودی/خروجی در کد: کلیدواژه‌های مسدود، جلوگیری از افشای پرامپت، محدودیت طول، محدودیت نرخ
- **دانشنامه**: تنها اطلاعاتی که دستیار اجازهٔ گفتنشان را دارد (قیمت، ارسال، ساعت کاری…)
- **اینباکس**: تاریخچهٔ گفتگو، توقف/فعال‌سازی AI برای هر مخاطب، پاسخ دستی
- **آزمایشگاه**: همان مسیر واقعی را بدون ارسال به اینستاگرام تست کن و ردپای هر مرحله را ببین
- **ذخیرهٔ امن**: توکن‌ها و کلید API با AES-GCM رمزنگاری می‌شوند
- **حالت‌های تاریک و راست‌به‌چپ**، طراحی واکنش‌گرا برای موبایل و دسکتاپ

## اجرا

پیش‌نیاز: **.NET SDK 10** (یا ۸ به بالا با تغییر `TargetFramework`).

### با Visual Studio (پیشنهادی در ویندوز)

روی فایل **`InstaMind.sln`** در ریشهٔ پروژه دوبار کلیک کن. سولوشن باز می‌شود،
پروژه به‌صورت خودکار انتخاب است؛ کافی است **F5** بزنی.

مرورگر روی <http://localhost:5298> باز می‌شود و همان پنل را می‌بینی.

- Visual Studio 2022 نسخهٔ 17.14 به بالا یا Visual Studio 2026 از **.NET 10** پشتیبانی می‌کند.
- اگر نسخهٔ قدیمی‌تری داری و .NET 10 را نمی‌شناسد، در `InstaMind.csproj` مقدار
  `<TargetFramework>` را از `net10.0` به `net8.0` تغییر بده (با .NET 8 SDK تست شده و بدون خطا build می‌شود).
- پروفایل اجرا (`http`) در `Properties/launchSettings.json` تعریف شده و مرورگر را خودکار باز می‌کند.

### از خط فرمان

```bash
dotnet run
```

یا `dotnet build InstaMind.sln` برای build کامل سولوشن، یا در ویندوز دوبار کلیک روی `run.cmd`.

هیچ دیتابیسی لازم نیست؛ همه‌چیز در پوشهٔ `data/` ذخیره می‌شود.

### HTTPS محلی (بدون دامنه)

برای تست روی `https://localhost` بدون خرید دامنه، پروفایل **`https-openssl`** آماده است:

```bash
dotnet run --launch-profile https-openssl
```

- گواهی self-signed با **OpenSSL** ساخته می‌شود (`SAN: localhost, 127.0.0.1, ::1`) و با
  پروفایل launch بارگذاری می‌شود؛ پورت‌ها `https://localhost:7052` و `http://localhost:5298`.
- برای اولین بار (فقط یک بار، در PowerShell):
  `certutil -user -addstore Root .run\localhost.crt`
  تا مرورگر اخطار «not secure» ندهد. (برای لغو: `certutil -user -delstore Root <thumbprint>`)
- اگر قبلاً با `dotnet dev-certs https --trust` کار کرده‌ای، پروفایل `https` هم همان گواهی dev را استفاده می‌کند.
- فایل‌های گواهی در `.run/` می‌مانند که در `.gitignore` هست؛ کلید خصوصی هرگز کامیت نمی‌شود.
- وبهوک و OAuth روی HTTPS محلی هم کار می‌کنند (`webhookUrl` و `oauthRedirectUri` خودکار `https` می‌شوند)،
  ولی متا فقط آدرس‌های عمومی را می‌پذیرد — برای اتصال واقعی همچنان به دامنه/تونل (ngrok و …) نیاز است.

### ۱) اتصال صفحهٔ اینستاگرام (بدون دادن پسورد)
برو به **صفحات اینستاگرام**:

1. یک اپ در [developers.facebook.com](https://developers.facebook.com) بساز و محصول **Instagram** را اضافه کن.
2. در Business login settings آدرس بازگشت را ثبت کن (در همان صفحه با دکمهٔ کپی بردار).
3. در **تنظیمات اپ متا** همان صفحه `Instagram App ID` و `App Secret` را وارد کن (فقط یک بار؛ برای همهٔ صفحه‌ها مشترک است).
4. روی **ورود با اینستاگرام** بزن؛ با همان یک ورود، کل فرایند تمام می‌شود: توکن ۶۰ روزه، پروفایل پیج و عضویت وبهوک خودکار انجام می‌شود.
5. برای اتصال **صفحهٔ دوم، سوم و…** دوباره همان دکمه (یا **+ افزودن صفحه**) را بزن و با اکانت آن صفحه وارد شو؛ هر صفحه توکن و لیست جداگانهٔ خودش را دارد.

برنامه کد را سمت سرور با توکن عوض می‌کند، توکن بلندمدت ۶۰ روزه می‌سازد، پروفایل را می‌خواند و عضویت وبهوک اکانت را خودکار ثبت می‌کند.
**پسورد هیچ‌وقت به این برنامه نمی‌رسد یا ذخیره نمی‌شود.**

### ۲) سرویس‌های هوش مصنوعی (یکی یا چندتا)
برو به **سرویس‌های هوش مصنوعی** → **+ افزودن سرویس AI** → یکی از پیش‌فرض‌ها را بزن
(OpenAI، OpenRouter، Groq یا Ollama لوکال) → API Key و مدل را وارد کن → **افزودن** → **تست اتصال**.

هر سرویسی که API سازگار با OpenAI دارد کار می‌کند
(مسیر `POST {BaseUrl}/chat/completions`). می‌توانی چند سرویس اضافه کنی؛ اولی «پیش‌فرض» است.

### ۲.۵) نسبت دادن AI به هر صفحه
در **صفحات اینستاگرام**، کنار هر صفحه فهرست **«این صفحه از کدام AI استفاده کند؟»** را باز کن و انتخاب کن:

- **پیش‌فرض**: از اولین سرویس استفاده کند؛
- یا هر سرویس دلخواه: چند صفحه می‌توانند روی یک AI باشند یا هرکدام AI جداگانه داشته باشند.

پیام‌های هر صفحه با همان سرویس جواب داده می‌شود (این انتخاب در دروازهٔ موضوع هم رعایت می‌شود).

### ۳) شخصیت و قوانین
در **شخصیت و قوانین**:
- نام کسب‌وکار و معرفی کوتاه
- **موضوعات مجاز** (هر خط یکی) — دستیار فقط دربارهٔ این‌ها حرف می‌زند
- **موضوعات ممنوع**
- **پاسخ خارج از موضوع** — همان متنی که برای سؤال بی‌ربط فرستاده می‌شود
- کلمات مسدود، حالت سخت‌گیرانه، محدودیت نرخ

با دکمهٔ **پیش‌نمایش پرامپت** ببین دقیقاً چه دستورالعملی به مدل می‌رود.

### ۴) دانشنامه
هر چیزی که دستیار باید بداند را اینجا بنویس. اگر اطلاعاتی نباشد، دستیار حدس نمی‌زند
و می‌گوید «با تیم چک می‌کنم».

### ۵) تست
در **آزمایشگاه** پیام بفرست و ببین کدام لایه‌ها اجرا شده‌اند:
`فیلتر کلیدواژه → دروازهٔ موضوع → تولید پاسخ → بازرسی خروجی → ارسال`.
از فهرست بالای همین صفحه می‌توانی **سرویس AI مورد نظر برای تست** را انتخاب کنی تا مطمئن شوی هر سرویس جداگانه جواب می‌دهد.

### ۶) تست نهایی با پیام مستقیم
1. کنار هر صفحه در **صفحات اینستاگرام** و کنار هر سرویس در **سرویس‌های هوش مصنوعی**، **تست اتصال** را بزن؛
   هر دو باید سبز شوند (تست صفحه با توکن همان صفحه از Meta جواب می‌گیرد و تست سرویس یک پاسخ واقعی از مدل می‌آورد).
2. حالت را روی **واقعی (Meta)** بگذار و از یک اکانت دیگر به پیج وصل‌شده **دایرکت** بفرست.
3. پیام باید در **گفتگوها** ظاهر شود و پاسخ AI با همان صفحه ارسال شود؛ در ردپای هر پاسخ می‌بینی کدام صفحه و کدام AI استفاده شده‌اند.

## اتصال واقعی به اینستاگرام

> ⛔ **ورود خودکار با یوزرنیم و پسورد در این برنامه وجود ندارد.**
> اینستاگرام برای دایرکت API رسمی دارد؛ ورود خودکار با پسورد خلاف قوانین متاست،
> معمولاً به بلاک شدن اکانت ختم می‌شود و پیام‌ها را هم از دست می‌دهی.
> به‌جایش **لاگین رسمی اینستاگرام (OAuth)** هست: پسورد را روی سایت خود اینستاگرام می‌زنی
> و برنامه فقط توکن می‌گیرد. اگر ترجیح می‌دهی دستی کار کنی، فرم توکن هم در همان صفحه هست.
>
> اگر آگاهانه خودکارسازی مرورگر می‌خواهی، بخش **«حالت مرورگر (Selenium)»** را پایین‌تر بخوان؛
> آن‌جا هم پسورد را برنامه نمی‌گیرد، ولی ریسک محدود شدن اکانت واقعی است.

پیش‌نیازها:

1. اکانت اینستاگرام **Professional** (Business یا Creator)
2. یک اپ در [developers.facebook.com](https://developers.facebook.com) با محصول **Instagram**
3. دسترسی‌های `instagram_business_basic` و `instagram_business_manage_messages`
4. یک آدرس **HTTPS عمومی** برای وبهوک (دامنه، یا تونل مثل `ngrok http 5298`)

> مسیر «Instagram Login» به صفحهٔ فیسبوک نیازی ندارد؛ پیج فقط در مسیر Facebook Login لازم است.

مراحل:

1. اپ متا را بساز و «API setup with Instagram login» را کامل کن.
2. در Business login settings آدرس بازگشت را ثبت کن:
   `https://دامنه-تو/oauth/instagram/callback` (در پنل خود برنامه کپی‌شدنی است).
3. در **صفحات اینستاگرام** از **تنظیمات اپ متا** مقادیر `Instagram App ID` و `App Secret` را وارد کن
   و روی **ورود با اینستاگرام** بزن.
4. در App Dashboard → **Webhooks**:
   - Callback URL: `https://دامنه-تو/webhook/instagram`
   - Verify Token: همان رشتهٔ دلخواه در پنل
   - فیلد `messages` را Subscribe کن (برنامه عضویت اکانت را هم خودکار ثبت می‌کند)
5. **تست اتصال** کنار هر صفحه و هر سرویس AI را بزن و یک پیام واقعی به پیج بفرست؛ باید در **گفتگوها** ظاهر شود.

### اگر ترجیح می‌دهی دستی توکن بگیری

1. با Graph API Explorer توکن بگیر و به **توکن بلندمدت** تبدیل کن.
2. در «اطلاعات اکانت» مقادیر `Instagram User ID`، `Access Token` و `Verify Token` را وارد کن.
3. حالت را روی **واقعی (Meta)** بگذار و ذخیره کن.

### قوانین مهم متا

- پاسخ فقط تا **۲۴ ساعت** بعد از آخرین پیام کاربر مجاز است.
- ارسال پیام تبلیغاتی/سرد (cold DM) مجاز نیست.
- هر پیام حداکثر **۱۰۰۰ کاراکتر**.
- در حالت Development فقط اکانت‌های تست کار می‌کنند؛ برای production باید App Review بگیری.

## حالت مرورگر (Selenium) — اختیاری، با مسئولیت خودت

اگر مسیر رسمی برایت جواب نمی‌دهد (چند پیج، پنجرهٔ ۲۴ ساعته، App Review)، برنامه یک مسیر دوم دارد:
یک **پنجرهٔ کروم واقعی** که خودت در آن لاگین می‌کنی و برنامه همان‌جا در صفحهٔ دایرکت می‌خواند و جواب می‌نویسد.
بعد از این‌جا، مسیر عادیِ برنامه (شخصیت، گارد‌ریل، دانشنامه، بودجه) بدون تغییر روی همین پیام‌ها کار می‌کند؛
فقط لایهٔ ارسال عوض می‌شود (`MessageRouter`).

> ⚠️ **این حالت خودکارسازی مرورگر است و با شرایط استفادهٔ اینستاگرام هم‌خوان نیست.**
> ریسک محدود شدن یا بسته شدن اکانت واقعی است. برنامه عامدانه هیچ لایهٔ «ضد‑تشخیص» ندارد:
> UA، Client Hints، اثر انگشت TLS/JA3/HTTP2، WebRTC، Canvas/WebGL و الگوی موس و کیبورد را دستکاری نمی‌کند،
> CAPTCHA را دور نمی‌زند و برای گم کردن IP پروکسی نمی‌چرخاند. کاری که می‌کند فقط این است:
> کم، آرام و با سقف.

### راه‌اندازی
1. Chrome نصب باشد. اولین اجرا Selenium خودش chromedriver را کنار می‌گذارد (یک بار شبکه لازم است).
2. صفحهٔ **حالت مرورگر** → **روشن کردن مرورگر**؛ پنجره روی صفحهٔ ورود اینستاگرام باز می‌شود.
3. همان‌جا با اکانت خودت وارد شو (کد دو مرحله‌ای هم همان‌جا). **پسورد را هیچ‌جای این پنل وارد نکن.**
4. حالت اتصال را روی **مرورگر (Selenium)** بگذار، «کارگر مرورگر روشن باشد» را روشن کن و ذخیره کن.
5. از یک اکانت دیگر دایرکت بفرست؛ در **گفتگوها** ظاهر می‌شود و پاسخ در همان پنجره تایپ و ارسال می‌شود.

نشست در `data/browser-profile` می‌ماند؛ بار بعد لازم نیست دوباره وارد شوی. وضعیت‌ها در `data/browser-state.json`
نگه داشته می‌شوند تا ری‌استارت باعث پاسخ تکراری نشود.

### رفتار انسانی که پیاده شده

| رفتار | تنظیم مربوطه |
|---|---|
| اسکن کم‌تکرار + پرش تصادفی | `browser.scanIntervalSeconds` / `scanJitterSeconds` |
| فقط گفتگوهایی که پیش‌نمایششان عوض شده باز می‌شوند | خودکار (اثر انگشت پیش‌نمایش) |
| حداکثر چند گفتگو در هر پاس | `browser.maxThreadsPerScan` |
| یک ارسال در هر بازه، برای همهٔ مخاطب‌ها | `browser.minGapBetweenSendsSeconds` |
| مکث طولانی برای همان مخاطب | `browser.conversationCooldownMinutes` |
| سقف سخت روزانه | `browser.dailySendCap` |
| سکوت بیرون از ساعت کاری (به وقت تهران) | `browser.workingHoursEnabled/Start/End` |
| «خواندن و فکر کردن» قبل از جواب | `browser.thinkMinMs` / `thinkMaxMs` |
| تایپ حرف‌به‌حرف با مکث طبیعی و مکث اضافه روی نقطه/ویرگول | `browser.typingMinMsPerChar` / `typingMaxMsPerChar` |
| فقط پاسخ به پیام ورودی، هیچ پیام سرد | خودکار (آخرین حباب باید ورودی باشد) |
| پاس اول بعد از ری‌استارت فقط ضبط می‌کند | خودکار (`Primed`) — بک‌لاگ قدیمی جواب نمی‌گیرد |
| همهٔ کارهای مرورگر یکی‌یکی و بدون هم‌زمانی | خودکار (یک قفل روی نشست) |

### ورود ذخیره‌شده (اختیاری)

در کارت **ورود ذخیره‌شده** یوزرنیم و پسورد را وارد کن و «ورود خودکار با حساب ذخیره‌شده» را روشن کن.

- پسورد با همان **AES-GCM** بقیهٔ رازها رمز می‌شود؛ در `data/config.json` فقط `enc:v1:…` می‌بینی و API همیشه `••••••••` برمی‌گرداند.
- «همین حالا وارد شو» اول تنظیمات را ذخیره می‌کند و بعد با همان حساب لاگین می‌کند.
- **کد دو مرحله‌ای و چالش امنیتی خودکار نمی‌شوند**: برنامه همان پنجره را باز می‌گذارد و در وضعیت می‌نویسد که منتظر توست.
- خطای خود اینستاگرام (پسورد اشتباه، کاربر ناموجود، محدودیت موقت) در کارت وضعیت به‌صورت قرمز نشان داده می‌شود.
- برای پاک کردن کامل: **پاک کردن حساب ذخیره‌شده** (فیلد خالی به معنی «همان قبلی را نگه دار» است، پس حذف مسیر جدا دارد).

> رمز داخل فایل رمزنگاری‌شده است، ولی کلیدش (`data/secret.key`) کنار همان فایل است؛
> هر کسی به این کامپیوتر و پوشهٔ `data/` دسترسی داشته باشد می‌تواند بازش کند.
> اگر این برایت مهم است، پسورد را ذخیره نكن.

### ۲۴ ساعته یا بازهٔ ساعتی

سوییچ **پاسخگویی ۲۴ ساعته** روشن باشد، شبانه‌روز جواب می‌دهد. خاموشش کن تا فقط بین
«از ساعت» و «تا ساعت» (به وقت تهران) کار کند؛ بازهٔ عبور از نیمه‌شب (مثل `22:00` تا `02:00`) هم پشتیبانی می‌شود.
بیرون از بازه، وضعیت روی **خارج از ساعت کاری** می‌رود و هیچ اسکن یا ارسالی انجام نمی‌شود.

### سرعت پاسخ (پروفایل‌ها)

| پروفایل | اسکن | فاصلهٔ ارسال | مکث هر مخاطب | فکر کردن | تایپ | سقف روز |
|---|---|---|---|---|---|---|
| 🐢 آرام | ۱۲۰±۴۰ ثانیه | ۷۵ ثانیه | ۲۰ دقیقه | ۵–۱۶ ثانیه | ۵۵–۱۴۰ms | ۵۰ |
| ⚖️ متعادل | ۴۵±۱۵ ثانیه | ۳۰ ثانیه | ۸ دقیقه | ۲٫۵–۷ ثانیه | ۴۰–۱۰۰ms | ۸۰ |
| ⚡ سریع | ۲۰±۸ ثانیه | ۱۲ ثانیه | ۳ دقیقه | ۱٫۲–۳٫۵ ثانیه | ۲۵–۶۵ms | ۱۲۰ |

انتخاب پروفایل، اعداد را یک بار به مقدارهای جدول برمی‌گرداند؛ بعدش هر کدام را دستی عوض کنی، همان می‌ماند.

**«Seen» چطور سریع می‌شود؟** هر بار که برنامه یک گفتگو را باز می‌کند، پیام برای طرف مقابل Seen می‌شود؛
پس فاصلهٔ اسکن همان تاخیر Seen شدن است. در پروفایل سریع، Seen حدوداً داخل ۲۰ تا ۳۰ ثانیه اتفاق می‌افتد و
جواب هم در همان چرخه تایپ می‌شود — به قیمت ریسک بیشتر.

### چیزهایی که عامدانه پیاده نشده

- **TLS/JA3/JA4 و HTTP/2 fingerprint**: با Selenium قابل کنترل نیست؛ handshake را Chromium و لایهٔ شبکه انجام می‌دهد.
  هر پکیجی که خلاف این را وعده بدهد، در بهترین حالت یک پروکسی محلی است که خودش امضای تازه می‌سازد.
- **Client Hints / `navigator.webdriver` / WebRTC / Canvas**: پنهان‌سازی نصفه‌نیمه خودش ناسازگاری تولید می‌کند
  و همان ناسازگاری سیگنال قوی‌تری است. این‌جا یک کروم واقعی و ثابت اجرا می‌شود، بدون وصله.
- **چرخش پروکسی و IP reputation**: برای رد گم کردن نیست. اگر شبکه‌ات مشکل دارد، همان را درست کن.
- **حل یا دور زدن CAPTCHA و WAF**: انجام نمی‌شود. اگر اینستاگرام چالش بدهد، برنامه همان‌جا می‌ایستد
  و در وضعیت مرورگر می‌بینی که منتظر است.
- **حرکت تصادفی موس/اسکرول برای فریب**: فقط همان کلیک و تایپی که برای کار لازم است انجام می‌شود.

### اگر ساختار DOM عوض شد

سه انتخابگر در بخش **پیشرفته** بدون بیلد دوباره قابل تغییرند:
`browser.threadLinkSelector`، `browser.composerSelector`، `browser.messageTextSelector`.
با **تست مرورگر** و `GET /api/browser/diagnostics` ببین برنامه در صفحه چه می‌بیند
(تعداد گفتگوها، وجود کادر نوشتن، وضعیت ورود).

## امنیت و داده‌ها

- توکن اینستاگرام، App Secret، API Key و پسورد حالت مرورگر با **AES-GCM** رمزنگاری و در `data/config.json` ذخیره می‌شوند.
- کلید رمزنگاری در `data/secret.key` است. **از آن پشتیبان بگیر**؛ بدون آن مقادیر رمزنگاری‌شده قابل خواندن نیستند.
- پوشهٔ `data/` را در گیت (یا هر جای عمومی) نگذار — در `.gitignore` هست.
- پنل مدیریت احراز هویت ندارد و برای اجرای محلی طراحی شده است. اگر آن را روی سرور عمومی می‌بری،
  حتماً پشت HTTPS و یک لایهٔ احراز هویت (reverse proxy با basic auth یا VPN) قرار بده.
- امضای `X-Hub-Signature-256` بررسی می‌شود؛ اگر `App Secret` وارد نشده باشد و حالت «واقعی» باشد،
  وبهوک با خطای 503 رد می‌شود (fail-closed).
- هرگز از کاربر رمز، کد یک‌بارمصرف یا شمارهٔ کارت نخواه — در پرامپت هم همین قانون هست.

## محدودیت‌ها و صداقت فنی

- **هیچ سیستمی صددرصد تضمین نمی‌کند** مدل از موضوع خارج نشود. سه لایهٔ گارد‌ریل احتمال را
  خیلی کم می‌کند، ولی موضوعات را دقیق بنویس و دانشنامه را کامل کن و خروجی‌ها را در آزمایشگاه تست کن.
- مدل ممکن است اشتباه کند یا اطلاعات قدیمی بدهد؛ دانشنامه منبع حقیقت است.
- اگر مدل پاسخ ندهد، متن «پاسخ خطای فنی» ارسال می‌شود (قابل تغییر).
- وبهوک باید سریع 200 بدهد؛ پردازش AI در پس‌زمینه انجام می‌شود و تکرار پیام‌ها با `message id` حذف می‌شود.
- این پروژه به هیچ سرویس شخص ثالثی وابسته نیست؛ فقط به API خودت و Meta.
- **حالت مرورگر تضمینی نیست**: اگر اینستاگرام ساختار صفحه را عوض کند، اسکن چیزی پیدا نمی‌کند تا انتخابگرها
  را به‌روز کنی؛ اگر چالش امنیتی بدهد، برنامه متوقف می‌شود و آن را دور نمی‌زند. هیچ وعدهٔ «بن نمی‌شوی» هم در کار نیست.

## عیب‌یابی

| مشکل | علت رایج |
|---|---|
| `verify: 403` در مرورگر | مقدار Verify Token در پنل و متا یکی نیست |
| `401` در وبهوک | امضای درخواست با App Secret نمی‌خواند (یا تونل بدنه را تغییر می‌دهد) |
| پیام ارسال نمی‌شود | توکن منقضی شده، دسترسی `instagram_manage_messages` نیست، یا پنجرهٔ ۲۴ ساعته گذشته |
| `Invalid OAuth access token` | توکن اشتباه/منقضی است؛ توکن بلندمدت بگیر |
| مدل جواب نمی‌دهد | Base URL یا کلید API اشتباه است؛ از «تست اتصال» کنار همان سرویس استفاده کن |
| پیام یک صفحه جواب نمی‌گیرد | در «صفحات اینستاگرام» ببین AI آن صفحه کدام است و «تست اتصال» همان صفحه را بزن |
| پاسخ خودکار یک‌هو قطع شد | احتمالاً سقف روزانهٔ آن صفحه پر شده؛ در همان کارت صفحه سقف را بالا ببر یا تا فردا صبر کن |
| پاسخ‌ها بی‌ربط‌اند | موضوعات مجاز را دقیق‌تر کن و `MaxTokens`/دما را کمتر کن |
| `پوشهٔ پروفایل مرورگر در حال استفاده است` | یک پنجرهٔ کروم دیگر با همان پروفایل باز است؛ همه را ببند یا پوشهٔ پروفایل دیگری بده |
| «کادر نوشتن پیام پیدا نشد» | انتخابگر `browser.composerSelector` با نسخهٔ فعلی اینستاگرام نمی‌خواند؛ از «تست مرورگر» و diagnostics ببین صفحه چه دارد |
| «فرم ورود اینستاگرام پیدا نشد» | صفحه هنوز بالا نیامده یا اینستاگرام فرم را جای دیگری نشان می‌دهد؛ شبکه/پنجره را چک کن و دوباره بزن |
| «اطلاعات ورود … نادرست است» | همان پیامی است که اینستاگرام داده؛ یوزرنیم/پسورد ذخیره‌شده را درست کن |
| «اینستاگرام کد تأیید یا چالش می‌خواهد» | دو مرحله‌ای/چالش را خودت در همان پنجرهٔ کروم کامل کن؛ برنامه دورش نمی‌زند |
| اسکن چیزی پیدا نمی‌کند | هنوز لاگین نیستی، یا `browser.threadLinkSelector` عوض شده |
| به پیام‌ها جواب نمی‌دهد ولی خطایی نیست | حالت روی مرورگر نیست، کارگر خاموش است، بیرون از ساعت کاری است، یا سقف روزانه پر شده |
